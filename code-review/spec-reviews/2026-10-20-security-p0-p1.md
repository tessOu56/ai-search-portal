## 1. Scope

Close P0/P1 from the 2026-10-20 security audit:

1. Fail-closed Bearer/`ADMIN_API_TOKEN` auth on governance write routes; reviewer/admin-only review with separation of duties.
2. Protect `GET /api/audit` (admin only).
3. Shared rate limiter (trusted IP, bounded in-memory store) on chat, MCP, knowledge search, and writes.
4. MCP gateway: auth, body cap, HITL gate for high-risk tools, `safeParse` on the envelope.
5. Agent-runtime stream: internal token when configured; production fail-closed.

Out of scope (P2): CSP headers, CORS fail-closed origin, OPA timeouts, CI `pnpm audit` gate.

## 3. Drift findings

| Area       | Finding                                                                         | Resolution                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity   | `role` / `requesterId` / `reviewerId` accepted from the client on submit/review | Drop `requesterId` and `reviewerId` from request bodies. Actor identity comes from Bearer or signed session cookie. Application OPA role is the authenticated principal's `opaRole`, not the form field. |
| Review SoD | Page action and JSON review have no role check                                  | `authRole ∈ {reviewer, admin}` and `user.id !== application.requesterId`.                                                                                                                                |
| Audit      | Public GET                                                                      | Admin only.                                                                                                                                                                                              |
| Rate limit | Chat trusts first `X-Forwarded-For`; unbounded Map                              | Platform IP (`x-real-ip` / `x-vercel-forwarded-for` when `VERCEL=1`); last XFF hop only with `TRUST_PROXY=1`; TTL + max keys.                                                                            |
| MCP        | Unauthenticated `request.json()`, parse can 500                                 | Auth + 64KB cap + `safeParse`.                                                                                                                                                                           |
| Demo UI    | Journey C uses unauthenticated form POSTs                                       | Same `requireUser` on page actions. E2E signs in via `POST /api/auth/session`. No login screen.                                                                                                          |

## 6. Breaking / migration

- **Breaking for anonymous clients**: governance writes, audit, chat, MCP return 401/503 without a token.
- Request bodies that only sent `requesterId` / `reviewerId` keep working (fields ignored/removed); identity is the token.
- Local/demo: set `ADMIN_API_TOKEN` (and optional reviewer/requester tokens). Production without `ADMIN_API_TOKEN` is fail-closed (503).

## 7. Notes

- Page UI `?sessionRole=` remains chrome-only and is not authorization.
- In-memory rate limit does not coordinate across Vercel instances (documented remaining risk).
- Evaluate POST may still accept a what-if `role` for policy preview; submit/review never trust it as actor identity.

## 8. Spec impact 摘要

- Zod + OpenAPI: drop client `requesterId`/`reviewerId`; add 401/403/429/503; Bearer security scheme; `/api/auth/session` BFF-only.
- Handler-mapping + MSW must enforce the same auth gate as LIVE routes.
