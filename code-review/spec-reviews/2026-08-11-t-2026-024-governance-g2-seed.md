| Area                           | Finding                                                                                                                                      | Resolution for G2                                                                                                                                                                                                                                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Departments                    | No first-class "department" concept — only free-text `owner` email                                                                           | Add optional `department: string` to `metadataAssetSummarySchema` (additive, non-breaking); populate on the `metalcraft-studio` pack from its existing owner roster                                                                                                                                                |
| Deprecated API / missing owner | No fixture asset exercises either edge case anywhere in the repo                                                                             | Add `api-legacy-quote` (deprecated, superseded-by pointer) and `dim-vendor-directory` (owner: "") to `metalcraft-studio/assets.json`. **Not** added to `scenario-lab` — that pack's exact page-boundary count (11 → 3 pages, last page 1 row) is a documented scenario contract in SCENARIOS.md and must not shift |
| Access-request seed            | `access-request-store.server.ts` starts empty; realistic data only appears after a user drives the full submit/approve UI flow               | Lazy, idempotent seed (`ensureGovernanceSeed()`) triggered on first `listAccessApplications()` call — **not** at module import, so pure unit tests that never list stay unaffected                                                                                                                                 |
| Test isolation                 | `governance-contract-parity.test.ts` calls `resetAccessApplicationStore()` in `beforeEach` and never calls `listAccessApplications()`        | `resetAccessApplicationStore()` marks the seed as already-applied so a reset store stays genuinely empty for test determinism (no silent reseed mid-test)                                                                                                                                                          |
| Audit log (real)               | `audit-log.server.test.ts` asserts **exact** `total` counts (`toBe(0)`, `toBe(2)`) against the real in-memory store                          | Do **not** seed `audit-log.server.ts` — a fresh real audit trail starting empty is correct product behavior anyway. | e2e determinism                | `access-review.spec.ts` uses `.first()` on pending-status list items after submitting a fresh request                                        | Seed timestamps are fixed in the past (2026-08-0x); `listAccessApplications` sorts by `updatedAt` desc, so a freshly-submitted e2e request always sorts to the top — `.first()` still targets it                                                                                                                   |
| Handler-mapping drift          | `submit` / `cancel` sub-resource routes (added in T-186) exist in both real routes and `metadata-handlers.ts` but are missing from the table | Add both rows                                                                                                                                                                                                                                                                                                      |

## 4. Six required edge cases → concrete fixtures

| Edge case         | Fixture                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| pending           | seeded application on `tbl-customer-profile` (PII), analyst/marketing, `pending_approval`                                                                                             |
| rejected          | seeded application on `dash-studio-margin` (confidential), reviewed → `denied`                                                                                                        |
| expired           | seeded application on `tbl-customer-profile`, aged past TTL → `expired`                                                                                                               |
| permission denied | seeded application on `tbl-rental-slot` (internal, no allow rule matches) → immediate `denied`, `need_approval:false` (direct policy deny, distinct from the reviewed-rejection case) |
| deprecated API    | new asset `api-legacy-quote` (tags include `deprecated`) + seeded application → `denied`                                                                                              |
| missing owner     | new asset `dim-vendor-directory` (`owner: ""`) + seeded application left `pending_approval` (no owner to route review to — admin escalation path)                                     |
